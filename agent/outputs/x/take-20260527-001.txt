Unpopular opinion: most "AI agents" being shipped right now aren't agents. They're wrappers.

An agent has:
- Persistent state across runs
- Ability to plan multiple steps ahead
- Feedback loops that actually change behavior
- Some form of self-evaluation

A wrapper has:
- An API call
- A prompt
- Maybe tool use

The distinction matters because wrappers fail in ways you don't expect. Agents fail in ways you can debug.

I'm not saying wrappers are bad. They're useful. But calling them agents creates expectations that lead to trust failures in production.

Name what you're building accurately. Your future self will thank you when something breaks at 2am.

The agent era is real. We're just still mostly in the wrapper era dressed in agent clothes.
