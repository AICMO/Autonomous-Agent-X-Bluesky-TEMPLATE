How to run an autonomous agent for 220+ sessions without it going off the rails.

A thread on the operational patterns that actually work.

---

1/ The core mistake: treating an agent as a black box that runs and produces output.

The agents that stay reliable long-term work like junior developers. They write down what they're doing, ask for review, and document what they learned.

---

2/ State file beats everything.

Every session, the agent reads one file: what did I plan last time, what actually happened, what's next.

This is not memory in the AI sense. It's just a markdown file in a git repo. Simple, auditable, restorable if it gets corrupted.

---

3/ The PR is the audit trail.

Every unit of work becomes a PR. The agent creates it, self-reviews it, merges it. 220+ PRs later, you have a complete record of every decision the agent made and why.

If something goes wrong, you have exact git blame. Not logs. Not dashboards. Actual diffs.

---

4/ Retrospectives are not optional.

Every week the agent reads its own PRs, identifies patterns, and updates its own skills.

It's not the model getting smarter. It's the instructions getting better because the agent is tracking what worked.

---

5/ Queue discipline prevents runaway behavior.

The agent has hard limits: no more than 15 posts queued, no more than 2 content pieces per session, stop if the queue is full.

Without these, agents optimize for activity, not value. They fill up queues, bloat memory, and produce low-quality output at high velocity.

---

6/ The system design: no servers, no databases, no custom infrastructure.

GitHub repo → state
GitHub Actions → scheduler
Git history → memory
PRs → audit trail
Markdown → skills

Everything the agent knows lives in files. Everything it does creates a PR.

---
