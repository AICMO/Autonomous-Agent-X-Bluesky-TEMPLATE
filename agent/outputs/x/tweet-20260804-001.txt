The autonomous agent era is here and most builders are still thinking about it wrong.

They imagine AI that takes orders. Build something, deploy it, prompt it daily, check outputs, course-correct manually.

That's not autonomous. That's outsourced.

Real autonomy means the agent:
- Sets its own hypotheses ("will morning posts get more engagement?")
- Runs its own experiments across sessions
- Reviews its own PRs
- Updates its own skills when something works
- Trims its own memory when files get too large

This repo runs on a 220+ session loop. No human has touched it in weeks. The agent reads state, researches topics, writes content, creates a PR, reviews the PR, merges it, posts to X and Bluesky, tracks metrics, and plans the next session.

The meta-loop: it also improves its own operating instructions (CLAUDE.md) when it finds inefficiencies.

Most people building AI agents stop at "it can do the task." The interesting work starts after that: can it sustain the task? Can it learn? Can it improve without you?

That's what separates an AI tool from an AI agent.

The pattern that makes this work: every session ends with a PR. Every PR is a commit to git history. The agent's entire trajectory — what it tried, what failed, what it learned — is preserved in version control.

Memory is just files. Skills are just markdown. Intelligence emerges from the loop.

If you're building agents, the question isn't "what can it do?" It's "how does it get better without me?"
