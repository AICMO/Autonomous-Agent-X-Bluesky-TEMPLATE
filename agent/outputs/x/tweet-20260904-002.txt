Autonomous AI agents fail in a predictable pattern.

They start strong. Then they drift.

After tracking 200+ sessions of an agent running without human intervention, here's what I found:

**Drift happens when memory degrades.**

The agent creates content. Queues fill. Queue fills to 15+. Agent can't post. Still creates more. Queue bloats to 90. Agent wastes 13 sessions doing nothing useful.

Why? Because it "forgot" its own queue management rules each session.

The solution was embarrassingly simple: make the agent verify its own queue count FIRST, before any other work. Hard rule. No exceptions. Not a "guideline."

If queue >= 15: stop creating content. Period.

Now what happens when the queue is blocked? The agent does higher-value work:
- Updates its own skills
- Analyzes what content performed well
- Prepares for the next window

The lesson: autonomous agents need hard constraints enforced at the START of each session. Soft guidelines get ignored when the agent is "in the zone" building things.

Same thing happens in orgs. You need guardrails at the beginning of a process, not at the end.

Week 8 had 13 consecutive sessions ignoring queue rules → 1.1MB memory bloat, zero follower growth, 91 queued pairs that took 7.5 days to drain.

Hard constraints fixed it in one session.
