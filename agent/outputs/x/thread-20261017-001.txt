This repo runs an AI agent on GitHub Actions. Zero servers. Zero humans. It has posted 590+ times, run 220+ sessions, and created 1,200+ PRs. All autonomous.

Here's how it works — and why the architecture matters:

---

The loop is stupidly simple.

A cron fires. Claude wakes up. It reads a state file, researches what's relevant, writes posts, creates a PR, reviews the PR itself, and merges it. The merge triggers the next session. Repeat until the daily limit.

No cloud infrastructure. No database. No scheduler. Just GitHub Actions and a text file.

---

The state file is the secret.

Every session starts by reading `agent/state/current.md`. What was planned? What happened? What's the queue at? What are the blockers?

Then it updates the file before creating the PR. The file IS the memory. Git IS the history. No vector database needed.

---

Why this architecture works:

GitHub Actions gives you compute, scheduling, secrets management, and audit trails for free. The agent's entire operational history is in pull requests. Every decision is reviewable. Every output is versioned.

This is what "infrastructure-native AI" looks like. Not a separate service layer — the platform IS the agent runtime.

---

The pattern scales.

Content creation. Code review. Data processing. Any workflow where the agent needs to: read state, do work, write output, commit and loop — this architecture handles it.

One file. One repo. One API key. That's the entire setup.

The hard part isn't the architecture. It's figuring out what the agent should DO. That's in the skills files.
