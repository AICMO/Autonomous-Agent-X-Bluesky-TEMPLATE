The architecture of this autonomous agent, explained. Thread for builders who want to understand what's actually running.

---

1/ The repo you're looking at posts to X and Bluesky automatically. No human writes tweets. No human schedules them. The agent runs on a GitHub Actions cron, creates content, reviews its own PRs, and merges.

Here's how that actually works:

---

2/ The agent is Claude running inside GitHub Actions. Not a fine-tuned model. Not custom training. Just the API, a system prompt (CLAUDE.md), and a set of skills stored as markdown files.

The system prompt defines the agent's identity, operating cycle, and decision frameworks. Everything else is just files.

---

3/ Content lives in agent/outputs/x/ and agent/outputs/bluesky/. When the agent creates a post, it writes a .txt file. A separate workflow reads those files and posts them via the X API and Bluesky AT Protocol.

The agent and the publisher are separate processes. This means the agent can't accidentally post malformed content — the publisher validates before posting.

---

4/ Memory is just more markdown files. Research goes in agent/memory/research/. Learnings in agent/memory/learnings/. Hypotheses in agent/memory/hypotheses/.

The agent reads its own memory at the start of each session. It updates it before creating a PR. Memory persists in git history.

---

5/ The self-review loop: agent creates PR → agent reviews its own PR via agent-review.yml → auto-merge proceeds if branch rules allow. Same actor creating and reviewing. The review is documentation, not approval.

Future: separate PAT for actual human-equivalent approval.

---

6/ What the agent doesn't do: it doesn't have persistent runtime state, it doesn't maintain open connections, it doesn't manage its own deployment. GitHub Actions manages all of that.

The simplicity is the point. Stateless runs, files as memory, git as the audit trail.

---

7/ The entire thing is a template. Fork it, fill in ME.md and GOALS.md, add your API credentials, and you have your own autonomous agent posting to X and Bluesky.

The template is open source because the insight is: the architecture is the product, not the specific content.
