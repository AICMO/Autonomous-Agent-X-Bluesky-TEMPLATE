# Learning: First Session — Template Repo Detection

Date: 2026-11-09
Session: S1

## What Happened
Agent launched on a fresh template repo. All configuration files contained placeholder bracket values:
- `ME.md` — `[Your Name]`, `[Your Background]`, etc.
- `GOALS.md` — `[YOUR GOAL HERE]`
- `agent/memory/pillars.md` — `[Pillar 1]`, etc.
- `agent/integrations/x/plan.md` — `@[YOUR_HANDLE]`, etc.
- `agent/state/current.md` — did not exist

No GitHub variables or secrets were configured (no platform credentials).

## Action Taken
Recognized that content creation is impossible without owner identity, goals, and platform credentials.
Created `agent/state/current.md` to document the state and provide clear next-steps for the owner.

## Key Insight
**The agent should detect a template state at the start of any session** by checking:
1. Does `agent/state/current.md` exist? If not, first session.
2. Does `ME.md` contain `[` brackets? If so, owner hasn't configured it.
3. Are GitHub variables empty? (`gh variable list`)

When all three are true, skip content creation entirely. Focus on initialization:
- Create state file
- Document what's needed
- Do NOT waste turns on research or content that can't be posted

## What Enables Content Creation (Checklist for Owner)
- [ ] Fill in `ME.md` with real name, background, expertise, links
- [ ] Fill in `GOALS.md` with real target metric and deadline
- [ ] Configure GitHub secrets: `X_API_KEY`, `X_API_SECRET`, `X_ACCESS_TOKEN`, `X_ACCESS_TOKEN_SECRET` and/or Bluesky equivalents
- [ ] (Optional) Configure GitHub variables for workflow settings
- [ ] Once ME.md is filled, agent can derive pillars and fill `agent/memory/pillars.md`
- [ ] Once credentials exist, agent can fill `agent/integrations/x/plan.md` and `agent/integrations/bluesky/plan.md`
